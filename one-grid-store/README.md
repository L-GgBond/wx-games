# 一格便利店 · one-grid-store

货架上的同款，凑满三个就消。篮子只有七个格子，装满了就卡住。

## 怎么跑

| 场景 | 操作 |
|---|---|
| 浏览器预览 | 直接打开 `index.html`（`game.js` 已入库） |
| 微信小游戏 | 微信开发者工具导入本目录，`compileType` 已是 `game` |
| 改代码 | `npm install` → `npm run watch` |
| 自检 | `npm run check`（`tsc --noEmit` + 构建 + 逻辑回归） |

## 玩法与数值

| 规则 | 数值 | 改哪里 |
|---|---|---|
| 货架 | 4 × 5 = 20 格，每格 3 件同类 | `src/logic.ts` → `COLS` / `ROWS` |
| 关卡 | 格子 `12 + 关×2`（封顶 20），商品 `2 + 关`（封顶 8） | `levelConfig` |
| 目标营业额 | `格子数 × 均价 × 0.62` | `levelConfig` |
| 篮子 | 7 格，加槽一次 +2，封顶 9 | `BASE_SLOTS` / `MAX_SLOTS` |
| 单价 | `8 + 种类序号 × 2` | `priceOf` |
| 撤回 | 每关 3 次，免费 | `UNDO_PER_LEVEL` |
| 星星 | 达成 1 星，超额 10% 两星，超额 35% 三星 | `starsOf` |

`levelConfig()` 是唯一的难度旋钮：改 `cells`、`kinds`、`0.62` 这三个数就能整体调松紧，改完跑 `npm run verify` 看「整局模拟」那段的结果。

## 三种状态怎么处理

| 状态 | 触发 | 玩家能做什么 |
|---|---|---|
| `play` | 正常进行 | 点货架、撤回、洗牌 |
| `stuck` | 放完一件后篮子满了且没消成 | 看视频加槽（7→9）、洗牌、重来；**不直接判负** |
| `win` | 营业额 ≥ 目标 | 进下一关 |
| `lose` | 货架全空但没达标 | 重来 |

## 目录

| 文件 | 作用 |
|---|---|
| `src/logic.ts` | 纯逻辑：货架生成、篮子插入与三消、卡住与救场、关卡配置 |
| `src/scenes.ts` | 首页 / 货架 / 篮子 / 三种弹窗 |
| `src/art.ts` | 8 种商品图形、货架格、篮子槽、进度条，无图片资源 |
| `src/ui.ts` | immediate-mode 按钮 / 文本 / 点击热区 |
| `src/platform.ts` | 微信与浏览器双端适配、激励视频 |
| `src/storage.ts` | 最高关卡、最高营收、引导标记 |
| `src/social.ts` | 微信侧离屏 Canvas 分享卡片 |
| `verify.mjs` | 47 条断言：货架数量守恒、三消、卡住、道具、整局模拟 |

## 上线前要改的

| 位置 | 现在 | 改成 |
|---|---|---|
| `project.config.json` → `appid` | `touristappid` | 自己的小游戏 AppID |
| `src/platform.ts` → `AD_UNIT_ID` | 空（演示模式直接发奖） | 激励视频广告位 ID，用在「加槽」和「洗牌」 |

## 已知取舍

- 每格固定 3 件同类，总件数一定是 3 的倍数，所以理论上能全部消完；难度全在篮子容量和点击顺序上。
- 篮子满了只标 `stuck` 不判负：这游戏 90% 的挫败来自「差一步」，留一个付费/看广告的出口比直接扣一条命更合理。
- 洗牌只重排还有货的格子，不改变商品构成，避免玩家刷出无解局面。
